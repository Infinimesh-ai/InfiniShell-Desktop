## 文案规范

- 中文面向用户统一使用“你”，不用“您”。
- 中文正文使用全角逗号、分号、冒号、括号和问号；代码、URL、端口、快捷键与命令语法保持原样。
- 中文界面省略号使用 `…`，代码占位符（例如 `sk-...`）除外。
- 品牌名后面的普通名词按中文语序处理，例如“InfiniShell SSH 扩展”。
- 英文采用句式大小写；产品名、Git、GitHub、Docker、Markdown、SSH、API 等保留规范大小写。
- 不用字符串拼接调整语序；带变量的句子必须在 Fluent 中使用 `{ $variable }`。
- 不翻译日志、遥测事件、配置键、协议字段、命令名、文件名和序列化枚举值。

## 新增或变动功能的强制本地化门禁

本门禁适用于所有新增用户功能和既有功能变动,是功能完成与提交的必要条件。不能因为“只改行为”“沿用旧消息键”或英文回退可用而跳过。若审计后确认没有用户可见文案变化,交付说明中也必须明确记录“无需本地化变更”。

1. 先盘点功能涉及的全部用户可见文案,包括 GUI/TUI 的标题、菜单、按钮、提示、占位符、工具提示、空状态、加载/错误信息、通知和无障碍文本;行为或语义变化时同时复核已有文案是否仍准确。
2. 在 `app/i18n/en/warp.ftl` 或 `warp_tui.ftl` 编写或更新完整、自然的英文源文案。
3. 同时在对应的 `app/i18n/zh-CN/` 文件中添加或更新相同消息键,并保持插值变量一致;不得把英文回退视为已完成简体中文支持。
4. 调用方使用字面量形式的 `crate::t!("message-id")`;动态键仅限已有兼容入口,不得新增硬编码界面文案或通过字符串拼接调整语序。
5. 运行本地化测试,再运行 `cargo check -p warp`;涉及 TUI 资源时同时运行对应 TUI 测试。门禁失败时功能不得提交或标记完成。
6. 文案可能影响布局时,在英文和简体中文界面分别检查截断、换行和控件尺寸,并在交付说明中记录结果。

```bash
cargo test -p warp --lib i18n::tests
cargo check -p warp
```

## 有意保留原文的边界

最终残留审计只保留以下不应进入 Fluent 的内容：日志与诊断上下文、遥测稳定值、协议负载、配置键与序列化标识、Shell 命令和代码示例、文件名与技术令牌、快捷键标记、品牌或提供商专名、用户输入及测试夹具。斜杠命令注册表中的英文描述是稳定元数据；所有实际菜单均通过 `localized_description()` 渲染本地化文本。
