# Windows 桌面验收的执行宿主

安装器、诊断脚本和 Explorer 即使使用相同账号、SID、Session 与逻辑注册表路径，也可能看到不同的实际状态。包身份 API 或脚本读回成功不足以证明用户桌面可见；不能单凭这类差异归因于安装器漏注册。

## 保持同一桌面上下文

1. 从现有普通 Explorer 桌面启动安装器、快捷方式、Windows PowerShell 5.1 采集器及 Shell URI 激活。
2. 保留每个动作的父子进程、会话、路径及完成回执；动作投递成功只表示提交，仍须检查实际结果。
3. 六阶段使用同一受测包与宿主，不能把自动化执行宿主的基线和 Explorer 的后续快照拼接。
4. 从 Windows 设置观察实际条目和卸载菜单，再执行本轮官方卸载。控制面板可能保留搜索缓存，必要时回到完整列表刷新后检查。
5. URI 需要实际新窗口及目标目录；快捷方式需要实际可交互窗口。注册表或 ShellExecute 返回值不能替代这些观察。

出现宿主可见性差异时保留两侧诊断，先使用原宿主的官方卸载器收尾对应诊断安装，再在已绑定桌面上下文建立新一轮。不能合并不同上下文的通过项，也不为诊断清除未知用户登记。

## 采集和审核

- 记录用户/系统 PATH 的原始字节、类型和存在状态；展开字符串摘要不能补证未采集的原始类型。
- OneDrive/Cloud Files 快捷方式按实际元数据读取结果判断，权限错误保持未知；不因此允许证据根使用普通符号链接、目录联接或未知重解析点。
- 独立原生注册表回归可以覆盖隔离键的缺失/空值、多个 owner、失败恢复与旧逻辑对照，但不等于完整产品包的 GUI 安装/卸载。
- 当前用户安装不证明管理员全用户安装；串行交错不证明并发事务安全；无法恢复的旧历史不能靠猜测重建。
- 用户数据只检查存在性时，报告明确限定范围；不要读取无关私人内容作为验收附件。
