# Windows 验收中的执行宿主一致性

2026-10-18 在候选 `v0.2026.10.14.16.45.oss_00`（源码 `5068dae9c75b79628865a0872684113647c204d8`）上发现：Codex exec 启动的安装器与采集器能写入并读回当前用户卸载项，但 Windows 设置和控制面板不显示。相同诊断脚本由现有 Explorer 启动时，Registry32/64 均读到卸载键不存在；两侧账号和交互会话相同，读取时尚未卸载。

这证明执行宿主相关的注册表可见性差异，不能据此假定安装器漏注册。两侧 `GetPackageFamilyName` 都返回无包身份，因此包身份 API、相同 SID、相同 Session 和相同逻辑注册表路径都不足以单独证明视图一致。具体底层隔离机制未确定。

本机恢复方法：保留失败证据，使用原宿主的官方卸载器收尾诊断安装；另建验收目录，让安装器、快捷方式启动、原生 PowerShell 5.1 采集和 Shell URI 激活统一从现有 Explorer 桌面上下文启动。保留每个动作的进程父子关系、会话及完成回执。六阶段快照不能跨宿主拼接。

实测同字节安装器经 Explorer 安装后，同一个 Settings 进程自动显示正确的 InfiniShell 条目和可用卸载菜单；从设置发起官方卸载成功，卸载后条目消失。控制面板旧搜索结果可能暂未刷新，需要回到完整列表重新加载后再搜索。仅注册表存在或 ShellExecute 返回成功，都不能替代界面观察。

R3 阶段仅修正验收执行方式和补充文档，安装器代码与二进制没有变更，无需本地化变更。当时没有运行或声称通过新的产品编译/云端门禁，也没有发布新候选；后续代码修复分别记录在下文。

本机交付材料位于独立验收根下的 `windows-v0.2026.10.14.16.45.oss_00-20261018-desktop-r3`：

- `desktop-runner.ps1`：限定桌面 Explorer 父进程，在同一 PowerShell 5.1 进程执行已绑定采集器或 URI helper，产出动作完成回执。
- `invoke-desktop-runner.ps1`：根据实际观察到的 Explorer 窗口句柄投递动作；返回只表示已提交，须检查 runtime 回执及快照。
- `results/RESULT.zh-CN.md`、`assessment.json`、`desktop-execution-binding.json`：完整结果、机器可读核对及补充摘要绑定。
- 原失败及 R1 归档保留不变，R2 诊断另归档。本轮存在 OneDrive 快捷方式正式采集 unknown（另有只读补证）和用户 PATH 原始摘要变化，报告保留这些边界。
