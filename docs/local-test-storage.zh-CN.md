# 本机 macOS 测试存储与清理约定

用户于 2026-09-28 指定内置盘固定目录 `/Users/zhishi/InfiniShell-Tests` 满足测试需求，并及时清理。本约定与该目录的 `README.md` 一致，仅约束用户这台 Mac 的测试执行；不改变产品默认路径，不向 Linux/Windows runner 硬编码本机路径或测试 feature。

## 每轮开始

- 固定根权限为 `0700`，只存可回收运行数据；`records/` 保留逐轮记录。每轮用新建的短 `r-<随机值>` 子目录（`0700`）作为该轮命令的 `TMPDIR`，不复用、搬动活动目录，不修改 `HOME` / `CODEX_HOME`。
- 在启动前解析真实路径，确认固定根及新子目录为当前用户所有的普通目录、与 `/Users` 的 `st_dev` 相同；核对 device/inode，确认路径及祖先无符号链接、无组/其他用户写权限，并拒绝嵌套挂载。路径或权限不满足安全测试时保留诊断，不修改既有目录、卷 ownership、全局 ACL 或 TCC 来绕过门禁。
- 源码、Cargo `target`/缓存、真实凭据及唯一验收证据不放入此临时根。沿用各任务已批准的构建缓存位置，不将本约定解释为迁移缓存的授权。

`records/<run-id>.json` 至少记录以下内容；不得写入 token 或凭据正文：

| 内容 | 必需记录 |
| --- | --- |
| 运行 | `run_id`、开始/结束时间、状态、命令及源码版本 |
| 目录身份 | 临时目录真实路径、device/inode、owner、权限 |
| 进程身份 | 主进程及已知后代/监督进程的 PID 与创建时间等身份；本轮专属 launchd 服务标签 |
| 归档 | 外置归档路径、索引或摘要，以及成功/失败结果和清理证明 |
| 清理 | `cleanup_ready`（默认 `false`）；删除后状态 `cleaned` 及清理时间 |

## 结束与每日补查

1. 等待命令结束，按本轮精确身份确认后代、监督进程、专属 launchd 服务及打开文件均已退出或释放。单个 PID 消失、宽泛进程名查询或一次有限权限的空查询不能独立证明清理完成；不得为清理而杀死未知进程。
2. 将命令、源码版本、结果、失败信息和小型证明先归档到外置盘 `InfiniShell-Archives`，并在对应归档保存本轮路径、状态和身份。外置盘不可用、尚需现场排查或退出证明不足时保留目录，`cleanup_ready=false`。
3. 满足退出与归档条件后设置 `cleanup_ready=true`，即明确可清理。删除前再次核对路径、owner、device/inode；只删除固定根下本轮目录，不追随符号链接、不跨设备或挂载点，不删除源码、`target`、缓存、凭据、外置归档。完成后保留 `records` 和外置收据，标记 `cleaned`。
4. 通常测试结束后即时清理；每日北京时间 `04:00` 补查结束已超过 `24` 小时且状态已完成、`cleanup_ready=true` 的遗留目录，并重复以上身份、退出与归档检查。活动、未知、被替换、挂载或符号链接目录一律保留，不能仅凭名称或年龄删除。
