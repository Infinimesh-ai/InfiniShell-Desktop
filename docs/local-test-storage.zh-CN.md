# 本机测试存储与清理约定

[English](local-test-storage.md)

本页规定共享安全门禁。机器专属测试根、归档位置和补查时间保存在不进入 Git 的 `.local/README.md` 及其引用文件中。构建或测试前必须读取；worktree 缺失时，通过 `git worktree list --porcelain` 定位主检出并读取其 `.local/README.md`。已有机器约定继续生效；配置缺失时先确定安全目录，不猜路径、不降低门禁。

## 每轮开始

- 测试根及每轮新建的短 `r-<随机值>` 目录权限为 `0700`；只为该轮设置 `TMPDIR`，不修改 `HOME` 或 `CODEX_HOME`，不复用或搬动活动目录。
- 解析真实路径，确认当前用户所有、普通目录、device/inode、与配置要求的内置盘同设备；祖先不得为符号链接或允许组/其他用户写入，拒绝嵌套挂载。不得修改既有目录权限、卷 ownership、ACL 或 TCC 绕过门禁。
- 源码、Cargo `target`、缓存、凭据及唯一验收证据不放入临时根；本约定不授权搬迁缓存。
- 在 `records/<run-id>.json` 记录开始/结束时间、命令、源码版本、目录与进程身份、归档位置、状态及默认 `false` 的 `cleanup_ready`。不得记录 token 或凭据正文。

## 真实多进程测试

若本机约定要求，真实 launchd/多进程测试使用短 `TMPDIR` 和 `--features warpui/test-util,rust-embed/debug-embed`，避免外置源码的资源读取阻塞。不因此启用 `release_bundle`、修改产品超时或将机器路径/feature 硬编码进产品及其他平台 runner。记录实际 feature、过滤器及源码/产物绑定；测试配置下通过不代表其他构建配置已验收。

## 收尾和补查

1. 按本轮精确身份确认命令、后代、监督进程和专属 launchd 服务全部退出，打开文件释放。单个 PID 消失、宽泛进程名查询或有限权限下的空查询不能独立证明完成；不杀死未知进程。
2. 将小型日志、源码身份、成功/失败结果和清理证明归档并核验。归档不可用、现场仍需诊断或退出证明不足时保留目录，`cleanup_ready=false`。
3. 全部门禁通过后才设置 `cleanup_ready=true`。删除前重新核对 owner、device/inode 和真实路径；不追随链接、不跨设备/挂载点，不删除源码、缓存、凭据、外置归档或唯一证据。清理后保留记录，标记 `cleaned`。
4. 通常完成即清理；补查时间沿用本机配置，只处理已完成、超过配置保留期且明确 `cleanup_ready=true` 的目录。活动、未知、被替换、挂载或符号链接目录均保留，不凭名称或年龄推定可删。
