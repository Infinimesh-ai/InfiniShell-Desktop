### 实施边界

- MCP 保留 rmcp 2.2，利用已有 cancellable request 和取消通知实现 30 分钟总期限、最多 5 秒取消等待；连接、派发、等待结果共用预算。工具只派发一次，资源读取重试保持原样。取消只针对当前请求，不关闭共享连接。未移植云 environment、OAuth 改造或纯依赖升级。
- rmcp 2.2 的无结果 SSE 结束仍可能等待至总期限；本轮不宣称具有 rmcp 3.5 的立即报错行为。测试使用真实 rmcp HTTP/SSE/duplex 传输，覆盖发送/取消阻塞和同连接并发请求。
- remote 请求 guard 在正常完成、发送失败、断连时不重复 Abort；外层取消则移除 pending 并发送 Abort。另以真实 LocalCommandExecutor、`crates/command` 和受控子进程验证服务器取消能够清理进程与 in-progress 请求。未引入云 clone 诊断。
- 本地 UI 框架没有上游 `try_update`；复用 `try_as_ref` 判断视图是否可借用，临时借用时延迟一次清理或同步；清理保留最后一个 pane 句柄，先转存历史再释放会话，设置回调读取最新状态。不新增框架 API 或终端模型锁。
- Linux/Windows 启动参数转发在单实例 IPC 前识别 crash recovery watcher；FreeBSD 不引用不存在的 crash recovery 模块。
- 历史菜单延迟动作执行时重新核对当前菜单模式。路径展开不使用宿主 home，不展开 `~other`，保留转义 tilde；没有引入 WSL 子进程枚举，也没有开放远程 `/open-file`。
