### TLS 依赖与证据边界

[RUSTSEC-2026-0382](https://rustsec.org/advisories/RUSTSEC-2026-0382) 指出，旧 WebPKI
可能接受包含已失信 emSign 中间公钥的证书链；`0.103.16` 加入拒绝规则。
本地 `rustls-webpki` 从 `0.103.13` 更新到 `0.103.16`，`webpki-root-certs`
从 `1.0.1` 更新到 `1.0.10`，保留 `0.26.11` 兼容封装。本地没有
`webpki-roots`，不引入上游锁文件中的额外包。

巡检时提出保留 AWS-LC 旧版本，实际解析证明不可行：WebPKI `0.103.16`
要求 `aws-lc-rs ^1.18`，固定回 `1.17.0` 的命令明确失败。最终解析为
`aws-lc-rs 1.18.2` / `aws-lc-sys 0.46.0`。与本地既有 `0.41.0` 对比，
包含 Windows 退出死锁修复的整个 `crypto/fipsmodule/rand/rand.c` 逐字节相同，
SHA-256 均为 `ab1f2639fa022a4ebbaf027bf932369d0d61f1e5cb139ba55cdb926ad3ab1166`。
这是源码证据，不能替代 Windows 构建和退出行为验证。

两项 `bundled_tls` 回归使用当前锁定的 Rustls WebPKI 验证器和 AWS-LC provider。
负例显式信任原根，必须得到底层 `CertDistrusted`，不能用过期、缺根或签名错误
代替；正例要求正常链通过。固定时间与公开证书的来源、摘要见
[夹具说明](../../crates/websocket/src/testdata/tls/README.zh-CN.md)。没有保存私钥，
没有修改产品信任库、证书验证策略或系统根。

Linux 的平台验证器使用 WebPKI，macOS/Windows 使用系统 API。离线回归不证明
真实 TLS 握手、实际系统信任锚或 macOS/Windows 原生验证已经验收。

### 终端事件顺序

- CLI 迟到激活回归通过本地历史模型产生子任务事件，确认完成命令保持隐藏、
  不恢复控制、不发出新的控制器事件；正常运行命令仍关联正确 task 并正常完成。
  原有 `Stop(false)` 与取消守卫保留，已有停止/显式恢复回归一并纳入验证。
- TerminalDriver 在匹配 `ExecuteCommand` 时记录活动块 ID，只有该块的
  `BlockCompleted` 才满足退出等待。缺失 Preexec 的兼容仍保留，非零退出码不丢失。
  `Exited` 释放 start/exit sender，沿用既有 `InvalidRuntimeState` 错误，避免悬挂。
  回归显式核验 bootstrap 已完成和非后台块前提，以确保旧判定确实可触发。
- 该驱动当前适用范围为独立 Gemini harness；不将其扩大为 Claude/Codex 托管
  runtime 的修复，也不将事件模型回归等同于真实三平台 Gemini/PTY 验收。

本地化审计：无需本地化变更。三项修复均未增加用户可见文案、消息变量或布局，
错误继续沿用原有路径；没有新增日志或遥测。
