### 浮窗尺寸

`Resizable` 的回调分派 `CLISubagentAction::Resize`，处理器将最新宽高记入当前窗口的 `ResizableData`，并请求既有 `workspace:save_app` 保存路径，沿用 250 ms 合并机制。仅重绘无法触发快照，正常退出也不会主动生成最终快照，因此此请求是持久化链路的必要部分。新浮窗复制该尺寸创建独立 handle，不共享拖拽状态。窗口快照通过 SQLite 保存两项 nullable float；旧窗口没有值时继续使用 360 × 320。现有尺寸边界、`team_uid`、tab groups 和窗口隔离保留。

迁移为 `crates/persistence/migrations/2026-10-07-000000_add_cli_subagent_window_sizes/`。schema 由既有 Diesel 配置在隔离数据库上生成，未手工修改生成列。回归覆盖真实 typed action 分派、保存请求到达并读取最新尺寸、新浮窗读取、两窗口保存并重开，以及没有新列的旧数据库升级。

### 图片与缩放

两条前景图片层均设置点击穿透，使图片继续显示、终端事件仍可命中。渲染回归通过真实 `GridHandler → render_grid → Presenter` 检查图片实际绘制及覆盖判定。

Unix 本地 shell 分别继承 `TERMINAL_BROWSER_DISPLAY_SCALE` 和 `PIXEL_DISPLAY_SCALE`，缺失时默认 `1`，之后仍允许会话环境覆盖。旧 [terminal-browser v0.7.3](https://github.com/zenbu-labs/terminal-browser/blob/v0.7.3/browser/src/session/session.tsx#L1618) 使用前者，新 [pixel 缩放实现](https://github.com/zenbu-labs/terminal-browser/blob/v0.13.4/pixel/packages/pixel/src/scale.ts#L6) 使用后者。没有足够依据扩大 Docker 或原生 Windows 的环境契约，本次不声称覆盖它们的缩放行为。

尺寸记忆、图片命中和环境变量没有用户可见文案变化，**无需本地化变更**。
