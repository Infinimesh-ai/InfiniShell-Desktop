# Source39 Grok 普通终端 GUI 验收

本轮使用 source39 隔离签名应用、固定 Grok 1.0.30 和应用界面安装的通知插件 0.1.2。父提交 af1040，仍为未提交候选。只有合成项目与隔离 HOME 参与；原生认证沿用已获用户授权的副本，结束后删除。完整证据见 [安全报告](validation/gui-official-39-grok-pty/report.safe.json)，其中列出 23 张真实截图及摘要。

## 实际结果

| 场景 | 结果 |
| --- | --- |
| 标题栏 Grok 启动与通知插件 | 真实入口启动固定版本，应用安装后在原生插件菜单刷新，观察 0.1.2、9 hooks；不是仅修改 registry |
| 英文、多行中文和文件 | 首轮记忆、中文多行及中文空格路径附件返回准确合成标记。使用 paste，不宣称真实中文输入法组合事件 |
| 技能菜单 | 应用 `/skills` 只显示人工可调用项；选择后原生结果正确，隐藏技能未显示 |
| 单次写入允许／拒绝 | 允许后准确字节落盘；另一创建被拒绝后原生 cancelled、文件不存在 |
| 已有文件编辑拒绝 | 原生先读取，再 search_replace 审批拒绝，原字节保持 |
| 审批等待中追加 | **失败**：富输入中完整正文可见，发送后未产生原生 turn；独立尾回车接受当时选中的单次 Yes，原写入完成。截图14–16及原生第7回合相互印证，不能计排队或 ACK 成功 |
| 等待中取消及继续 | Ctrl+C 后原生 cancelled、目标不存在；下一轮正确回收首轮记忆 |
| 完整应用重启 | 先退出 CLI，再退出应用；审计确认无活动原生会话。重启后历史 19 文件不变、无自动模型输入；显式 `--resume` 同原生 ID，新输入返回首轮记忆 |
| 真实代码评审入口 | 合成仓库行级意见经按钮进入富输入，包含准确路径、L2 和意见；新回合返回指定评审标记，无工具执行 |

共 13 次 UI 发送尝试，原生 events 证明 12 个 turn，全部 yolo_mode=false。第2次为自动化 typeText 换行误发的独立 English 输入，计入实际模型数，不计中文验收。第9次追加尝试没有成为模型回合，不能称为第13个模型输入。所有确认回合均有 terminal outcome；read_file 的原生 allow 记录不等于人工逐笔审批。取消／拒绝分别保留原生 decision，不混为成功。

文件选择器一次旧回调被应用拒绝；之后正确文件经实际选择器加入。另一次快捷键误开空分屏已关闭，没有新增模型输入。合成项目中只提交 review.txt 基线以开启实际评审；未操作产品主仓库的 Git 状态。

## 收尾与限制

七项用户全局配置均保持内容和元数据不变；两次完整退出后应用和原生活动数均为0。原始授权缓存未改，隔离认证副本已删除。报告只包含安全字段、摘要与合成截图，不归档凭据或原生历史正文。

本轮整体 **未通过**。已发现的富输入误审批必须修复后另行验证；缺少可信 prompt-ready 事件时不能自动发送 CR 或声称排队成功。独立 edit_allow 未执行、真正 IME 与完整双语布局未执行、父子托管与 SSH／tmux 不属于此 GUI 证据。source39 成功子项不能覆盖后续候选，也不是最终同提交三平台验收。
