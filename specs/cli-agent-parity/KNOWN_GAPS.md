# CLI 当前限制与未验范围

当前发布状态见[发布入口](../../docs/releases/README.zh-CN.md)，支持能力见[能力矩阵](CAPABILITY_MATRIX.md)。原批准合并范围 G01–G10、V03 已关闭；以下列出仍需如实保留的范围，不重开已完成任务。

## 平台验证范围

| 项目 | 当前边界 | 何时补验 |
| --- | --- | --- |
| V01：完整模型生命周期 | Linux 三款 CLI 完整生命周期延期；Windows Codex/Grok 的完整生命周期仍未计通过 | 需要宣称对应平台完整支持，或相关启动、审批、恢复链发生变化时 |
| V02：物理输入法 | Linux 真实组合输入与候选选择延期；Windows 已有人工确认，但完整连续物理输入证据不足 | 输入行为变更或需要正式覆盖时；不单为补录像重复已有人工操作 |
| V05：真实审批双语布局 | Linux 以及 Windows Grok 的真实待决、允许、拒绝布局未完整覆盖 | 审批界面调整或集中验证相关流程时 |
| 发布包桌面生命周期 | 以当前发布入口为准；源码 CI、旧包结果和安装器静态检查不能替代本版 GUI、URI 与卸载 | 对实际新包按变更影响决定范围 |

## V04 — 图片投递与模型理解分别验收

Codex 的类型化图片投递已有证据，但错误识色回答不能记为理解正确。仍需一条可判定的应用内图片理解链，分别核对请求字节、实际模型和回答；独立原生 CLI 正例不能替代应用链，也不据此断言已确认投递缺陷。不扩展为所有格式、模型与平台组合已验。

## 非阻塞跟进

| 项目 | 边界 |
| --- | --- |
| `MAC-SETTINGS-SEARCH-ZH-01` | 中文“连字”搜索可发现性不足；英文 `ligature` 入口可用 |
| `UBUNTU-SSH-EMPTY-CLIP-01` | 窄侧栏 SSH 空状态可能裁切，拖宽可恢复 |
| `UBUNTU-INPUT-MODE-01` | 含中文的命令曾被识别为 Agent 输入，切回 Shell 后可执行；需要定向复现，与输入法问题分别判断 |

## 持续兼容边界

- Codex 活跃回合 `Steer`、Claude 原生合并/后续轮次和 Grok 后续回合排队具有不同语义，不能统一宣传为即时 steer。
- 普通终端 Stop、Escape、EOF 或基础通知不证明工具完成或整棵进程树退出；未知结果保持未知。
- CLI 版本发现、可执行文件升级、通知插件和托管协议兼容分别核验。更新可用不代表新版本能力已受测。
- 文件卡传递本地路径引用，不保证任意二进制解释，也不自动传输远程文件。
- 固定文件、命令或技能策略限制宿主工具权限，不构成操作系统沙箱保证。
- 缺陷关闭须满足对应真实场景；不能用其他平台成功、静态检查或安全拒绝替代未验功能。
