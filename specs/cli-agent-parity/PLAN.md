## 目标与范围

三款 CLI 在 InfiniShell 中具备可靠、一致的终端交互体验和本地任务管理能力。P0–P5、[消费者自动升级](CLI_AUTOUPDATE.md)、开发与验收版本维护均属本 Goal。以固定版本小步迭代，升级发现与托管兼容分别判断，不因上游连续发布反复更换验收基线。

- 覆盖 macOS Apple Silicon、Linux x64、Windows x64 桌面 GUI、其中的普通终端与应用托管任务；SSH／tmux 单独验收。2026-09-26 用户明确不再支持 macOS Intel，Codex 等三款 CLI 的 Intel 适配与验收均不在本目标范围。
- 保留真实协议、模型、技能、MCP、权限与输入差异，不跨 CLI 自动复制配置，不降低其他 CLI 的已有能力制造一致性。
- `warp_tui` 前端、云端任务、模型 API／BYOP、SuperGrok OAuth 重接是独立范围，不作为本 Goal 前置条件。
- Grok 桌面入口默认开放；实际操作仍受版本、来源、认证、权限及能力检查约束。

## 产品约定

普通终端保留 CLI 原生 TUI、登录和审批，应用提供工具栏、富输入、上下文与可信通知；需要人工审批时回到正确终端。托管模式由应用管理进程、输入、审批、结果、取消和恢复，只开放相应版本已验证的操作。两者共享身份和展示约定，但普通 PTY 不能未经上游支持直接转为协议会话。

| 用户动作 | 必须达到的行为 |
| --- | --- |
| 发现与启动 | 识别命令、安装、版本、身份、项目目录及可用模式；管理命令不误判为交互；安装不等于登录 |
| 输入与上下文 | 中英文、真实 IME、多行和长文本不丢失、不重复；草稿及焦点正确；附件、文件、技能和评审意见按真实语法投递 |
| 状态与结果 | 运行、等待用户、成功、失败、取消、连接中断语义明确；缺可信事件时显示未知，只有真实完成才显示成功 |
| 审批与停止 | 允许／拒绝只作用于当前请求；托管模式具有审批回路或明确选择的无交互拒绝策略；取消完成须有真实依据 |
| 继续与恢复 | 活跃任务重关联、历史会话继续、失败重试和新建分别处理；恢复失败保留记录，不偷偷新建或重放副作用 |
| 插件与更新 | 区分缺失、过旧、禁用、不兼容、失败及恢复；CLI 更新与插件更新独立核验，保留用户配置 |
| 本地子任务 | 按父权限上限派发；支持运行中追加、父子双向消息、分阶段 ACK、进度、最终结果与持久恢复 |
| 原生设置 | 模型、推理档位等只展示实际版本支持的选项，默认继承 CLI 设置，不伪造统一能力 |

## 技术约束

- 复用 `CLIAgent`、Harness、`use_agent_footer`、现有状态与持久化组件；静态能力、版本、插件、认证与开关独立判断，保留旧序列化值及未知值读取行为，不重构成通用插件平台。
- Codex 使用 app-server；Claude 使用双向结构化流／control；Grok 使用 ACP。先验证安装版本的真实握手、审批、取消、恢复和终态，再扩展适配，不照搬文档中未实现的方法。
- 独立验证每款括号粘贴、Enter 时序、中文组合输入、图片方式、技能来源与 `$`／`/` 语法；覆盖空格、引号、中文及 Windows／远端路径。
- 结构化事件、OSC 777、基础通知、本地输入、进程退出的证据强度不同。事件绑定应用实例、代次及原生会话／回合 ID，处理重复、乱序、双通道和旧回调；Grok 兼容 Claude hooks 时仍报告真实 CLI 身份。
- 普通 PTY Stop hook 不能单独证明完成；同回合后续事件仍须有效。已绑定任务但结果未知时保存 `Unconfirmed`，保留会话／代次占用，不生成最终成功结果。单个工具失败、开始停止或进程退出均不能直接充当任务终态。
- 移除 Claude／Codex 固定绕过审批及沙箱参数；启动不得改写 Claude 全局信任、onboarding 或危险提示。不能仅删参数而留下不可见审批。固定权限配置不是操作系统沙箱。
- 子进程统一走 `crates/command`，按平台处理进程组、Windows Job／ConPTY、PowerShell、EOF 和退出。取消与清理只作用于当前拥有的进程树；PID 不能单独作为恢复或终止依据。
- 持久保存应用任务 ID、CLI 类型／版本、原生会话 ID、目录、模式、非敏感选项、父子关系、代次、消息状态、结果与附件引用；schema 变化走 migration。
- 父权限快照与消息归属在创建时绑定；父→子追加、子→父进度／阻塞／结果有关联 ID、顺序、状态及 ACK。`native_protocol` 与 `application_history` 确认分开，均不单独证明模型完成；重投不得重复执行，取消后的消息不得进入新代次。
- 活跃任务重新关联须核对主机、目录和实例；历史继续显式使用原生 ID，同一会话不得并发恢复。重启先恢复记录，不能自动重发已执行输入。
- 插件采用受控版本与真实发布来源，保留禁用及无关配置，失败只回退本次拥有的变更；未知来源或并发编辑不得直接覆盖。

实施按依赖拆小提交：P0 后优先修复配置与权限，P1／P2 并行补交互和插件，再完成 P3／P4 与 P5。公共枚举、状态、启动和持久化由单一写入负责人整合；原生适配器接口稳定后可按不重叠写入域并行。阶段交付不缩减原 Goal。

## 验证要求

三款 CLI 在目标平台分别验证：**新建 → 两轮交互 → 审批允许／拒绝 → 追加指令 → 取消 → 继续 → 应用重启 → 恢复 → 结果回收**。普通终端与托管模式分别记录，父子消息链不能由根任务成功替代。

1. 识别：绝对路径、别名、环境前缀、空格路径和管理命令；本机安装不能证明 SSH 远端就绪。
2. 输入：真实 IME 候选选择、中英混排、多行、长文本、快速 Enter、取消与切换 pane；图片投递和模型理解分别判断。
3. 上下文：文件、图片、技能、评审意见的来源、路径、权限、实际接收、顺序和恢复；远端图片须真实传输。
4. 事件与状态：缺字段、未知事件／版本、重复／乱序、双通知、Claude／Grok 共存、晚到回调；工具失败后继续、崩溃、仅基础通知、无终态退出及取消／最后输出竞态。
5. 权限与进程：首次登录、启动失败、允许／拒绝／取消／超时、过期审批、无交互拒绝、父任务关闭、完整进程树清理且不误伤其他会话。
6. 恢复与消息：记录过旧／缺失、会话不存在、项目移动、CLI 升级、重复恢复、追加 ACK、进度／结果回收、重启续传、消息重投与恢复失败。
7. 插件与升级：缺失、过旧、禁用、离线、中断、不生效、不兼容、卸载／回退、配置保持；自动升级另满足[事务门禁](CLI_AUTOUPDATE.md)。
8. 英文与简体中文同键同变量、实际界面布局／截断／换行／错误提示；剪贴板成功不代替真实 IME。

每个功能变更先跑受影响模块，再完成强制门禁：

```sh
cargo test -p warp --lib i18n::tests
cargo check -p warp
cargo nextest run --no-fail-fast -p warp --lib -E 'test(cli_agent) | test(local_harness) | test(harness_availability)'
cargo nextest run --no-fail-fast --workspace --exclude command-signatures-v2
```

涉及其他 crate 时增加相应测试；GUI 集成测试使用 `crates/integration`。按跨平台验证技能对包含实际修改的同一提交完成 macOS、Linux、Windows 的相关门禁，SSH／tmux 单独实测。模拟、编译、选定测试或其他平台成功不能替代真实产品链，跳过项不能记通过。

外置盘仅保留构建缓存；需要启动的验收二进制／应用复制到内置盘、核对摘要后运行，不依赖外置盘授权弹窗。测试使用隔离项目与配置，不泄露认证材料。验证结论记录提交、CLI 版本、平台、模式、命令／场景、结果及未覆盖范围；本目录保留结论与必要回归夹具，不继续累积逐轮日志和原始截图。
