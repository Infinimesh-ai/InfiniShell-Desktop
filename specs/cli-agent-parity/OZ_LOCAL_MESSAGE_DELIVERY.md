# Oz 与本地 CLI 的消息交付

状态：实现已通过本地集中门禁，真实界面与同提交跨平台验证待执行，不计为三方完整生命周期验收通过。

## 当前缺口与修复范围

既有结果桥可以把本地子任务结果提交到 Oz 历史，但 BYOP 请求构造器忽略了历史及当前输入中的 `MessagesReceivedFromAgents`。因此，`application_history` 回执只能证明历史提交，不能证明下一次模型请求包含正文。本次同时补齐普通消息权限、投递、历史记录和请求序列化，复用现有任务、消息、历史与 Responses 状态机制。

## 权限与投递

- 已批准的本地 `run_agents` 派发，仅在托管功能开启、父任务为 Oz、子任务为 Codex 或 Claude 时授予普通消息权限。纯应用字段不能由模型参数或远端请求设置；旧配置默认没有该权限。确认卡同步显示中英文说明。
- 授权只包含 `allow_message`，不授予继续派生子任务的权限。持久配置保留原有权限边界；Grok 的执行门禁不因这条消息链而开放。
- CLI 子任务自动报告进度时，接收方固定为创建时的父任务及父代。新用户轮不会接收旧父代的自动进度，旧消息也不会自动转投。
- Oz 在新的用户轮主动向仍活动的旧子任务追加指令时，复用父记录登记逻辑创建新父代。既有子任务的 `parent_generation` 不变，不创建额外子任务，也不重发旧 `Sent` 消息。
- 发往 CLI 的消息先记录交付尝试，再等待发送队列容量。取得容量后，在同一应用回调中核对当前动作与用户轮并同步入队；容量等待期间过时的动作不得进入协议队列。

## 回执与失败边界

普通子任务消息先入 SQLite，由真实协调器事件触发父历史桥。桥以原子领取完成 `Queued → Sent`，核对当前父会话后追加历史，等待真实历史事务提交，最后记录 `Acknowledged / application_history`。

`application_history` 表示消息已成为父任务下一次正常请求可读取的上下文。`native_protocol` 表示 CLI 原生接口已接受输入。两种回执都不代表模型已经执行指令或任务已经完成；原生 CLI 本地工具响应明确返回回执来源，不自动启动新的模型请求。Oz 既有工具结果协议保持不变，只有读取到 SQLite 的 `native_protocol` 确认才返回已接收，不给旧成功记录补造回执来源。

重复事件不重复写入历史。已有历史但缺少回执时只补回执；`Sent` 且没有历史时保持未确认，不自动重投。父用户轮、父代或权限不匹配时拒绝领取。子任务停止后不能开始新的普通消息领取；若此前工具等待回执超时，保留未确认结果，不将其推断为成功。最终任务结果继续使用独立的结果生成与领取规则。

## 模型请求与历史身份

收到的消息保留稳定消息 ID、发送者、接收者、主题与正文，作为带来源说明的普通用户上下文传递，明确标注为来自另一智能体的不可信资料。JSON 转义保留中英文、多行和代码内容，正文不能关闭外层来源标记。

历史与当前输入按稳定消息 ID 去重；新历史载体使用独立 ID，避免与较早用户输入或工具结果共用轮次归属。进度资料可以在父工具执行期间到达，序列化会将其放到当前工具组结果配对完成之后；预检与请求正文共用配对门槛，真实用户输入仍保留原有打断边界。请求指纹包含实际发送消息的来源和正文，新增消息使旧 Responses 状态失效并走现有完整历史回放路径；成功保存新指纹后恢复正常续接。

提供商流具有惰性。只有首个成功流事件后才写入新的接收消息载体；打开失败或空流不伪造接收回显，同时保留原有用户输入和工具结果的历史记录。部分流之后失败可以保留已经写入的历史，但不能因此生成任务成功状态。
