# CLI 验证范围与门禁

本页说明如何解释和补充 CLI 验证。当前正式版本、发布结果和明确未验范围统一见[发布入口](../../docs/releases/README.zh-CN.md)及 [CURRENT_STATUS.json](CURRENT_STATUS.json)，功能限制见[当前限制](KNOWN_GAPS.md)。

## 已验证范围的含义

原批准合并范围 G01–G10、V03 已关闭。已有验证覆盖固定 CLI 版本、模式和构建的 macOS 功能链，以及相关 Linux/Windows 源码、通知、升级与进程监督门禁；不表示全部平台在线模型、完整输入法、真实审批布局或后续发行包均已通过。

| 证据 | 可以说明 | 不能替代 |
| --- | --- | --- |
| 静态检查、编译及单元测试 | 选定源码路径的类型、逻辑与回归合同 | 实际 CLI、模型、桌面或安装包运行 |
| 固定协议夹具 | 已记录协议格式及异常分支 | 真实身份、认证、网络及未来版本兼容 |
| 原生 CLI/适配器运行 | 指定 CLI、模型、模式的请求与结果 | 应用 GUI、其他版本或其他平台 |
| GUI 与双语布局 | 实际构建、语言、视口与操作结果 | 未运行的恢复路径或其他屏幕布局 |
| 安装器静态核验 | 来源、包内身份、资源及签名状态 | 安装、URI 唤起、正常退出和卸载 |
| 完成/清理回执 | 同一代次的可信终态或资源释放 | 其他代次、未知后代或未知服务 |

## 变更后的检查

先读取根 [AGENTS.md](../../AGENTS.md) 和适用的本机配置。按影响运行聚焦回归，提交前执行 `cargo check`；用户功能变化还须完成英中审计、`cargo test -p warp --lib i18n::tests` 和 `cargo check -p warp`，文案影响布局时检查两种语言。涉及 TUI 时追加对应测试和真实屏幕检查。

跨平台变化使用[现有 preflight](../../.github/workflows/cross-platform-preflight.yml)及仓库跨平台验证约定。需要全工作区回归时执行：

```sh
cargo nextest run --no-fail-fast --workspace --exclude command-signatures-v2
```

脚本入口保留在 [script/cli-agent-parity](../../script/cli-agent-parity/)；运行前阅读具体脚本参数、目标版本和授权范围。`live`、安装、升级或恢复脚本可能调用真实 CLI、模型和用户配置，不能作为普通离线测试批量执行。

## 结果记录

- 绑定源码 SHA、实际二进制/安装包摘要、平台、CLI/插件版本、模式和模型；不同构建分别计证。
- 区分通过、失败、跳过、未执行和证据不足；保留原错误，不将预期负对照写成正例。
- 图片字节进入请求、原生 ACK、模型回答与应用历史分别检查。恢复测试确认同一任务和原生会话，且没有重复发送。
- 父子任务核对权限上限、允许/拒绝、越界拒绝、消息关联和取消收尾；不能用无审批的只读探针证明权限保护。
- 清理按[测试存储约定](../../docs/local-test-storage.zh-CN.md)执行；`cleanup_ready=false` 不因进程暂时不可见或文档更新而解除。
- 只共享必要脱敏结论和来源；本机原始日志、配置、数据库与截图按[证据约定](../../docs/evidence/README.zh-CN.md)保存。
